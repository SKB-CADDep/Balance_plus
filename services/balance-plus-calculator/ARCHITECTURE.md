# Balance Calculator Service — Architecture Overview

В данном документе описана архитектура микросервиса расчета тепловых балансов турбин. Сервис построен по принципам чистой архитектуры (Clean Architecture) с использованием паттерна Anti-Corruption Layer (ACL) для безопасной интеграции унаследованного математического ядра.

## Высокоуровневая структура слоев

| Слой | Директория | Технологии | Ответственность |
| --- | --- | --- | --- |
| **API Layer** | `app/api/` | FastAPI, Pydantic | Прием запросов, валидация JSON-контрактов, роутинг. |
| **Service Layer** | `app/services/` | Python, SQLAlchemy (CRUD) | Бизнес-логика, работа с БД, постановка задач в очереди. |
| **Adapter Layer (ACL)** | `app/core/` | Python | Трансляция Pydantic-схем в легаси-объекты и обратно. |
| **Math Core Layer** | `app/core_math/` | Python (Legacy) | Чистые математические вычисления и термодинамика. |
| **Shared Packages** | `requirements.txt` | Python | Внешняя математика (конденсаторы, штоки) без сетевых вызовов. |

## Подробное описание потока данных (Data Flow)

Архитектура строго однонаправленная. Внутренние слои (Математика) ничего не знают о внешних слоях (API, Базы данных).

### 1. Слой API (Роутеры)

**Точка входа запроса.** Фронтенд или другой микросервис делает HTTP-запрос к эндпоинту (например, `POST /api/v1/balance/calculate`).

* **Что происходит:** FastAPI автоматически валидирует входящий JSON с помощью Pydantic-схемы `CalculationInput`. Отсекаются неверные типы данных, отсутствующие обязательные поля или недопустимые перечисления.
* **Что передается дальше:** Валидный Python-объект `CalculationInput` передается в Service Layer. Никакой бизнес-логики здесь нет.

### 2. Слой Service (Оркестрация и CRUD)

**Управление бизнес-процессом.** Этот слой отвечает за "подготовку сцены" для математики.

* **Что происходит:** * Если для расчета нужны данные из базы (например, сохраненный ранее режим, нормативные кривые или параметры конкретной турбины), сервисный слой дергает CRUD-операции.
* CRUD-функции используют сессии SQLAlchemy для извлечения моделей БД и маппят их в дополнения к нашему `CalculationInput`.
* В production-режиме именно здесь формируется Celery Task: сервисный слой передает задачу в брокер (Redis/RabbitMQ) и немедленно возвращает клиенту `HTTP 202 Accepted` с `task_id`.


* **Что передается дальше:** Полностью сформированный и обогащенный объект `CalculationInput` передается в адаптер (внутри воркера).

### 3. Слой Adapter (Anti-Corruption Layer)

**Защитный барьер.** Переходная зона между современным стеком и легаси-кодом.

* **Что происходит (Input Mapping):** Адаптер берет `CalculationInput` и поштучно перекладывает его поля в старый класс `NetworkModel`. Восстанавливается 1-based индексация массивов, заполняются поля `model.nodes` и `model.links`, задаются `solver_settings`.
* **Вызов ядра:** Адаптер вызывает функцию `solve(model, trace, props)` из слоя Core.
* **Что происходит (Output Mapping):** После завершения расчета адаптер берет мутировавший `NetworkModel` и объект `CalculationReport`, извлекает из них нужные цифры и упаковывает всё обратно в строгий Pydantic-контракт `CalculationOutput`.
* **Что передается дальше:** Чистый `CalculationOutput` возвращается обратно в сервисный слой для сохранения в БД или отправки ответа клиенту.

### 4. Слой Math Core (Ядро)

**Изолированная термодинамика.** Это оригинальные файлы `solver.py`, `ppi.py`, `psi.py`, `dgi.py`, `pit.py`, отвязанные от GUI (PyQt).

* **Что происходит:** Выполняется жесткий итеративный цикл. Узлы (`nodes`) и связи (`links`) мутируют на каждом шаге. Просчитываются давления по участкам (PPI), энтальпии (PSI), баланс расходов (DGI) и температуры (PITW).
* **Интеграция со смежными системами:** Если ядру нужно посчитать конденсатор или шток клапана, оно **не делает** сетевой HTTP-запрос (чтобы не блокировать Event Loop на 50 итерациях). Вместо этого оно импортирует чистую функцию из разделяемого пакета (Shared Core Package, например, `condenser_math`), который устанавливается как зависимость.
* **Что передается дальше:** Ничего. Ядро просто завершает работу функции `solve()`, оставляя результаты внутри переданного ему объекта `NetworkModel`.

## Правила разработки

* **Запрет на импорты:** Слой `core_math` не имеет права импортировать ничего из `app/api`, `app/db` или `app/schemas`.
* **Тестируемость:** Математическое ядро покрывается модульными тестами (через вызов адаптера) в полной изоляции от поднятия FastAPI сервера или подключения к PostgreSQL.
* **Чистота логов:** В слое ядра запрещены `print()`, прямые вызовы логгера или всплывающие окна. Все события собираются в объект `CalcTrace` и прокидываются наружу.
