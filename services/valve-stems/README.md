# ⚙️ Valve Stems (Штоки Клапанов) — Документация микросервиса

Данная директория содержит исходный код бэкенда микросервиса Valve Stems (Штоки клапанов), а также смежные компоненты инфраструктуры.

## 📌 Требования

* [Docker](https://www.docker.com/) для запуска инфраструктуры (БД, Redis).
* [Poetry](https://python-poetry.org/) для управления зависимостями Python (вместо устаревших pip или uv).

---

## 🌳 Структура проекта и Архитектура

Чтобы вам было легко ориентироваться в кодовой базе, ниже приведена карта микросервиса. Проект разделен на три основных компонента: `backend` (API и математика), `frontend` (UI интерфейс) и `db` (хранилище дампов).

```text
📁 valve-stems/
├── 📄 .env                     # Глобальные переменные окружения (пароли, порты)
├── ⚙️ docker-compose.yml       # Оркестрация локальной инфраструктуры (БД, Redis, API)
│
├── 📁 db/                      # [ИНФРАСТРУКТУРА БАЗЫ ДАННЫХ]
│   ├── 📄 init.dump            # ВАЖНО: Эталонный дамп БД. Именно отсюда разворачивается база!
│   └── ⚡ restore.sh           # Скрипт для накатывания дампа на локальную БД PostgreSQL
│
├── 📁 frontend/                # [КЛИЕНТСКОЕ ПРИЛОЖЕНИЕ (UI)]
│   ├── 📁 src/client/          # Автогенерируемый OpenAPI-клиент для типизированных запросов к Backend
│   └── 📁 src/components/      # React-компоненты (UI)
│
└── 📁 backend/                 # [REST API И МАТЕМАТИЧЕСКОЕ ЯДРО]
    ├── 📁 app/
    │   ├── 📁 adapters/        # Паттерн "Адаптер": преобразование внешних данных под внутренние интерфейсы
    │   ├── 📁 alembic/         # Миграции БД (Используются только для обновления структуры поверх дампа)
    │   ├── 📁 api/routes/      # HTTP-контроллеры (Эндпоинты FastAPI: расчеты, турбины, генерация схем)
    │   ├── 📁 core/            # Настройки приложения, подключение к БД, конфигурация логирования
    │   ├── 📁 crud/            # Функции для взаимодействия с БД (Create, Read, Update, Delete) через SQLAlchemy
    │   ├── 📁 domain/          # [БИЗНЕС-ЛОГИКА]: Изолированное математическое ядро (valve_physics_engine.py)
    │   ├── 📁 middleware/      # Промежуточное ПО (например, сквозное логирование запросов)
    │   ├── 📁 models/          # ORM модели SQLAlchemy (описание структуры таблиц в БД)
    │   ├── 📁 schemas/         # Pydantic модели (Валидация входящих JSON и генерация Swagger UI)
    │   ├── 📁 scripts/         # Утилитарные скрипты (сидирование БД, проверка DrawIO, подготовка к запуску)
    │   └── 📁 tests/           # Автотесты (Pytest: API, модульные, Tavern-тесты для интеграций)
    ├── ⚡ entrypoint.sh        # Стартовый скрипт контейнера (ожидание БД)
    ├── 🔒 poetry.lock          # Жестко зафиксированные версии Python-зависимостей
    └── 📦 pyproject.toml       # Конфигурация Poetry (список пакетов, настройки Ruff и Pytest)
```

### Архитектурные паттерны:
1. **Изоляция предметной области (DDD):** Вся сложная инженерная математика (`seuif97`) находится строго в папке `domain/`. Роуты (`api/`) отвечают только за прием JSON и не содержат формул.
2. **Contract-Driven Development:** Фронтенд общается с бэкендом на основе Pydantic-схем (`schemas/`), генерирующих Swagger. Это исключает ошибки передачи неверных типов данных.

## 🐳 Запуск инфраструктуры (Docker Compose)

Запуск локальной среды разработки (базы данных и очередей) осуществляется с помощью Docker Compose из корня проекта:
```bash
docker-compose up -d db redis
```

## 💻 Рабочий процесс Бэкенда (Workflow)

Мы используем `Poetry` для строгого контроля зависимостей. Все команды ниже выполняются из директории `./backend/`.

**1. Установка зависимостей:**
```bash
poetry install
```

**2. Активация виртуального окружения:**
```bash
poetry shell
```
*Убедитесь, что ваш редактор кода (VS Code / Cursor) использует интерпретатор Python, созданный Poetry.*

**3. Запуск сервера:**
В соответствии с матрицей портов Balance+, этот сервис запускается на порту **5253**:
```bash
poetry run uvicorn app.main:app --host 0.0.0.0 --port 5253 --reload
```

## 🧪 Тестирование бэкенда

Тесты написаны с использованием `pytest`. Для запуска тестов выполните:
```bash
poetry run pytest
```
Если вы хотите передать дополнительные аргументы (например, остановиться на первой ошибке), используйте:
```bash

```

**Покрытие тестами (Coverage):**
При запуске тестов с флагом покрытия генерируется файл отчета `htmlcov/index.html`. Откройте его в браузере, чтобы увидеть, какие строки кода покрыты тестами, а какие — нет.

## ⚠️ Управление базой данных и Миграции (Alembic)

> **[ENGINEERING CONTEXT]**
> Из-за наличия сложных эталонных справочников (геометрии клапанов, свойства материалов), **ПЕРВИЧНАЯ инициализация базы данных через Alembic строго запрещена.**
> Не используйте команду `alembic upgrade head` на пустую базу данных!

1. Восстановите структуру и начальные данные БД **из SQL-дампа** (используйте порт **5254**).
2. Alembic используется **только для инкрементальных изменений** схемы поверх уже восстановленной базы.

**Создание новой миграции (если вы изменили ORM-модели):**
```bash
poetry run alembic revision --autogenerate -m "Краткое описание изменений, например: Add column to User"
```
После проверки сгенерированного файла в папке `alembic/versions/`, примените изменения к БД:
```bash
poetry run alembic upgrade head
```
Обязательно закоммитьте новые файлы миграций в Git.
