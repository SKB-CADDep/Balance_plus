# 🧪 E2E Тестовая документация: Valve Stems Frontend

В данном модуле реализовано полное покрытие сквозными автотестами (Playwright) интерфейса калькулятора параметров штоков клапанов паровых турбин (`services/valve-stems/frontend`).

Тесты изолированы от внешнего бэкенда с помощью гибкого сетевого мокирования, следуют паттерну **Page Object Model (POM)** и покрывают весь пользовательский путь от поиска оборудования до выгрузки расчётных схем и отчётов.

## 🚀 Быстрый старт и запуск

Все команды выполняются из директории `services/valve-stems/frontend`:

```bash
cd services/valve-stems/frontend
```

### Основные команды запуска:

| Команда | Описание |
| :--- | :--- |
| `npm run test:e2e` | Запуск **всех** E2E-тестов в headless-режиме (Chromium) |
| `npm run test:e2e:ui` | Интерактивный UI-режим Playwright с таймлайном и скриншотами |
| `npm run test:e2e:ci` | Режим для CI/CD пайплайнов (с автоповторами и отчётом) |
| `npx playwright show-report` | Открытие последнего сгенерированного HTML-отчёта |

### Запуск отдельных наборов тестов:

```bash
# 1. Smoke инфраструктуры и навигации
npx playwright test tests/e2e/smoke.infra.spec.ts --project=chromium
npx playwright test tests/e2e/smoke.navigation.spec.ts --project=chromium

# 2. Шаг 1: Поиск турбин
npx playwright test tests/e2e/calculator.turbine-search.spec.ts --project=chromium

# 3. Шаг 2: Выбор клапанов
npx playwright test tests/e2e/calculator.stock-selection.spec.ts --project=chromium

# 4. Шаг 3: Ввод параметров и валидация
npx playwright test tests/e2e/calculator.stock-input.spec.ts --project=chromium

# 5. Шаг 4: Результаты, Excel, Draw.io
npx playwright test tests/e2e/calculator.results.spec.ts --project=chromium
```

## 📦 Каталог моковых данных

Все сетевые вызовы перехватываются через `page.route()`, что гарантирует независимость тестов от работы бэкенда и БД:

* **`turbines-search.json`**: Список турбин с привязанными клапанами и номерами станций (`GET /api/v1/turbines/search`).
* **`turbine-valves.json`**: Детальная структура клапанов турбины (`GET /api/v1/turbines/{id}/valves`).
* **`units.json`**: Справочник единиц измерения давления, температуры и энтальпии (`GET /api/v1/utils/units`).
* **`calculation-result.json`**: Результат мульти-расчета с массивами $G_i, P_i, T_i, H_i$, деаэратором и эжекторами (`POST /api/v1/calculations/calculate`).
* **`calculation-error.json`**: Ошибка валидации термодинамических параметров (код 500/400).

## 📝 Детальное описание наборов тестов

### 1. Инфраструктурный тест (`smoke.infra.spec.ts`)
* ✅ **Проверка порта и запуска:** Проверяет успешный запуск dev-сервера на порту `3001` без ошибок браузерной консоли.

---

### 2. Оболочка и навигация (`smoke.navigation.spec.ts`)
* ✅ **Главная страница:** Проверка заголовка `WSAPropertiesCalculator`, карточек возможностей и перехода по CTA-кнопке на `/calculator`.
* ✅ **Меню навигации:** Проверка роутинга между разделами `/about`, `/help` и `/calculator`.
* ✅ **Страница Help:** Проверка открытия раздела и кликабельности FAQ-аккордеона с раскрытием текста ответа.
* ✅ **Страница About:** Открытие статической страницы без ошибок и крашей интерфейса.
* ✅ **404 NotFound:** Переход по несуществующему URL `/unknown-route`, отображение ошибки `404 / Page not found` и возврат на главную по кнопке «Go back».

---

### 3. Шаг 1: Поиск турбины (`calculator.turbine-search.spec.ts`)
* ✅ **Пустое состояние:** Без ввода символов лишний сетевой запрос не отправляется, отображается подсказка *«Введите параметры для поиска»*.
* ✅ **Поиск по марке турбины:** Проверка работы дебаунса (500 мс), отправка запроса и рендеринг карточек турбин.
* ✅ **Комплексная фильтрация:** Проверка передачи параметров `station`, `factory`, `valve` в query-параметрах URL запроса.
* ✅ **Кнопка «Очистить»:** Сброс всех значений инпутов и возврат к стартовому состоянию.
* ✅ **Выбор турбины:** Клик по найденной турбине скрывает поиск и открывает Шаг 2 с именем выбранного проекта.
* ✅ **Обработка ошибок API (500):** Показ красного блока *«Произошла ошибка при поиске!»* с текстом от бэкенда без зависания UI.
* ✅ **Пустой результат:** Отображение сообщения *«Проекты не найдены. Попробуйте изменить критерии поиска.»*.

---

### 4. Шаг 2: Выбор клапанов (`calculator.stock-selection.spec.ts`)
* ✅ **Загрузка клапанов:** Отображение списка клапанов турбины с бейджами типов (`РК`, `СК`) и числом участков.
* ✅ **Блокировка кнопки «Далее»:** Кнопка неактивна (`disabled`) при `totalSelected = 0`.
* ✅ **Указание количества (`quantity`):** Ввод количества для одного или нескольких клапанов с динамическим обновлением текста кнопки `Далее (Выбрано: N)`.
* ✅ **Кнопка «Изменить проект»:** Возврат на Шаг 1 к форме поиска турбины.
* ✅ **Переход на Шаг 3:** Переход к вводу параметров с передачей выбранного состава клапанов.
* ✅ **Пустой список клапанов:** Отображение сообщения *«Для данного проекта клапаны не найдены.»*.

---

### 5. Шаг 3: Ввод параметров и валидация (`calculator.stock-input.spec.ts`)
* ✅ **Дефолтные значения:** Проверка дефолтных параметров ($P_{fresh} = 130$, $t_{fresh} = 555$, $P_{air} = 1.033$, $T_{air} = 20$, $P_{lst} = 0.97$).
* ✅ **Переключение режимов $T \leftrightarrow H$:** Переключение радиокнопок между «Температура» ($t_{fresh}$) и «Энтальпия» ($h_{fresh} = 832.9$).
* ✅ **Геометрия отсосов:** Динамическое формирование полей давлений в камерах согласно формуле $count\_parts - 2$.
* ✅ **Валидация полей:** Проверка ошибок обязательности, запрета буквенного ввода и ограничения точности (не более 4 знаков после запятой).
* ✅ **Смена единиц и формирование `MultiCalculationParams`:** Смена единицы измерения в dropdown (на `МПа`), валидация структуры тела POST-запроса расчёта и переход к результатам.
* ✅ **Кнопка «Изменить состав клапанов»:** Корректный возврат на Шаг 2 к выбору количества.

---

### 6. Шаг 4: Результаты расчёта и экспорт (`calculator.results.spec.ts`)
* ✅ **Happy Path отображения таблиц:** Проверка одновременного рендеринга Таблицы 1 (участки), Таблицы 2 (потребители) и Итоговой сводной таблицы отсосов.
* ✅ **Параметры $G, P, T, H$:** Отображение расчётных величин расходов, давлений, температур и энтальпий.
* ✅ **Сводка отсосов:** Отображение бейджей и строк деаэратора и эжекторов.
* ✅ **Экспорт в Excel:** Клик по кнопке «Скачать Excel», генерация книги XLSX и появление toast-уведомления *«Excel файл успешно создан»*.
* ✅ **Генерация Draw.io:** Скачивание сгенерированного файла `.drawio`.
* ✅ **Ошибка генерации Draw.io:** Показ toast-уведомления об ошибке при 500 статусе сервиса схем.
* ✅ **Ошибка API расчёта (500):** Показ toast-ошибки с деталями от сервера и сохранение пользователя на Шаге 3 без перехода на пустой экран результатов.
* ✅ **Возврат назад:** Кнопка «Изменить параметры расчета» возвращает на Шаг 3 с сохранением всех ранее заполненных данных.

## ⚙️ Особенности конфигурации и окружения

1. **Единый порт:**  
   Vite Dev Server и Playwright BaseURL согласованы на `http://127.0.0.1:3001`.

2. **Автоподдержка системного Chromium (Arch Linux / Ubuntu):**  
   В `playwright.config.ts` встроена автоматическая проверка `/usr/bin/chromium`. Если тесты запускаются в Linux-дистрибутивах без встроенных браузеров Playwright, раннер автоматически использует системный Chromium.

3. **Безопасность сетевых моков:**  
   Все регулярные выражения моков строго ограничены путями API (`/\/api\/.*\/.../`), что исключает случайный перехват файлов сборщика Vite.
