## 🛠 Предварительные требования

Перед запуском убедитесь, что находитесь в директории фронтенда калькулятора конденсаторов:

```bash
cd services/condenser-calculator/frontend
```

Установите зависимости, если они не были установлены ранее:
```bash
npm install
```

> **Примечание для пользователей Arch Linux:**  
> Playwright использует системный браузер Chromium (`/usr/bin/chromium`). Если он отсутствует, установите его через пакетный менеджер:
> ```bash
> sudo pacman -S chromium
> ```

## 🧪 Unit-тестирование (Vitest)

Unit-тесты покрывают работу функций парсинга диапазонных вводных данных (`src/utils/parser.ts`).

### Команды запуска:

* **Разовый запуск тестов:**
  ```bash
  npx vitest run src/utils/parser.test.ts
  ```

* **Запуск в режиме наблюдения (Watch Mode при разработке):**
  ```bash
  npx vitest
  ```

---

## 🎭 E2E-тестирование (Playwright)

E2E-тесты проверяют пользовательские сценарии ввода параметров, взаимодействия с формой и отображения матриц результатов.

### Команды запуска:

* **Основной запуск E2E-тестов (проект Chromium):**
  ```bash
  npx playwright test tests/e2e/specs/calculation-flow.spec.ts --project=chromium
  ```

* **Интерактивный UI-режим (с графическим интерфейсом и отладкой):**
  ```bash
  npx playwright test --ui
  ```

* **Просмотр детального HTML-отчета после прогона:**
  ```bash
  npx playwright show-report
  ```

## 🏛 Архитектура и Паттерны

### 1. Page Object Model (POM)
Тесты строго следуют паттерну POM. Хардкод CSS/XPath локаторов внутри `.spec.ts` файлов **запрещен**. Вся работа с DOM инкапсулирована в классах страниц:

* `tests/e2e/pages/BasePage.ts` — базовый класс с общей навигацией и переключением темы.
* `tests/e2e/pages/CondenserFormPage.ts` — взаимодействие с формой ввода параметров калькулятора (построено на устойчивых `getByRole` локаторах).
* `tests/e2e/pages/ResultMatrixPage.ts` — проверка результатов расчета и матрицы таблиц.

### 2. Мокирование API (Изоляция)
Для обеспечения высокой скорости выполнения тестов и независимости от состояния внешнего бэкенда/БД, все сетевые запросы API перехватываются с помощью `page.route()`:

* `GET /api/v1/condensers` — эмуляция списка оборудования.
* `GET /api/v1/condensers/{id}` — эмуляция детальных характеристик конденсатора.
* `GET /api/v1/materials` — эмуляция списка материалов трубок.
* `POST /api/v1/calculate` — эмуляция успешного расчета с возвратом структуры матриц.
