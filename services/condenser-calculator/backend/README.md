Локальный backend микросервиса расчета конденсаторов на базе **FastAPI** и **SQLAlchemy**.

## Что делает эта директория?
Здесь находится ядро веб-сервиса: REST API для приема параметров от клиента, бизнес-логика маршрутизации, взаимодействие с базой данных (PostgreSQL) для хранения справочников (геометрии конденсаторов, материалы) и запуск изолированного математического ядра для расчетов.

> **[ENGINEERING CONTEXT]**
> Математические алгоритмы (метод Бермана, Метровиккерс и др.) намеренно изолированы от HTTP-контроллеров FastAPI. Это гарантирует, что тяжелые вычисления не заблокируют веб-сервер, а изменения в роутах не повредят инженерные формулы.

```text
│   └── 📁 src/components/      # UI-компоненты (формы ввода параметров трубных пучков)
│

    ├── 📁 alembic/             # Скрипты миграций БД
    ├── 📁 app/
    │   ├── 📁 api/routes/      # HTTP-контроллеры (Эндпоинты расчетов и справочников)
    │   ├── 📁 core/            # Настройки, Celery-воркеры, валидаторы и логирование
    │   ├── 📁 crud/            # Операции с БД (чтение конденсаторов и материалов)

    │   ├── 📁 schemas/         # Pydantic модели (Валидация JSON-контрактов)

    │       └── 🐍 calculation_engine.py   # Вычислительный движок
    │
    ├── 📁 scripts/             # Утилиты для генерации отчетов и сидирования БД
    ├── 📁 tests/               # [АВТОТЕСТЫ]
    │   ├── 📁 api/             # Тестирование HTTP-эндпоинтов
    │   ├── 📁 unit/            # Тесты отдельных функций и конвертеров
    │   └── 📁 validation/      # ⚠️ Верификационные тесты математики (по эталонным режимам Бермана)
    │
    ├── 🐳 Dockerfile
    ├── 🔒 poetry.lock
    └── 📦 pyproject.toml
```

## Настройка окружения (.env)
Для локального запуска необходимо задать переменные окружения. Создайте файл `.env` в корне директории `backend/` (рядом с этим README) на основе следующего примера:

```env
# Пример .env файла
DATABASE_URL=postgresql+asyncpg://<db_user>:<db_password>@localhost:5255/<db_name>
SECRET_KEY=<your_secret_key_here>
DEBUG=True
```

## Руководство по запуску

Мы используем пакетный менеджер **Poetry**. Все команды выполняются из директории `services/condenser-calculator/backend`.

### 1. Запуск инфраструктуры (Docker)
Для работы локального бэкенда требуется база данных и брокер сообщений. Из **корня всего проекта** поднимите инфраструктуру:
```bash
docker-compose up -d
```

### 2. Установка зависимостей бэкенда
Возвращаемся в папку сервиса (`services/condenser-calculator/backend`) и ставим пакеты:
```bash
poetry install
```

### 3. ВАЖНО: Работа с Базой Данных (PostgreSQL)
> **[!WARNING] Строгий запрет на чистые миграции**
> Обратите внимание на папку `db/materials/`. Структура БД содержит сложную предметную область и десятки эталонных справочников теплопроводности сталей. **НЕ ИСПОЛЬЗУЙТЕ** команду `alembic upgrade head` на пустую базу! 
> Базу данных (порт `5255`) необходимо разворачивать **только из SQL-дампа**.

### 4. Запуск сервера API (FastAPI)
Запустите бэкенд с привязкой к закрепленному за этим сервисом порту **8010**:
```bash
poetry run uvicorn app.main:app --host 0.0.0.0 --port 8010 --reload
```
Интерактивная документация (Swagger UI) будет доступна по адресу:  
**http://localhost:8010/docs**

## Маршрутизация (Справка по проекту)
Во избежание конфликтов портов, за каждым сервисом в экосистеме Balance+ закреплен свой порт. Учитывайте это при настройке CORS.

| Компонент / Сервис | Локальный URL / Порт | Внутренний Docker порт |
|--------------------|----------------------|------------------------|
| **API Backend** (Текущий) | `http://localhost:8010` | 8000 |
| **PostgreSQL DB**  | `localhost:5255` | 5432 |
| **Frontend** (UI) | `http://localhost:5173` | - |
